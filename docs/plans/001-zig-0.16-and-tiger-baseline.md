# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Move zoltraak from Zig 0.15.2 to **0.16.0** — green `zig build test` and green CI on 0.16 —
while installing the kingdom's Tiger Style floor (`tidy` build step, assertions on the hot
modules, honest docs). Ship the result as **v0.3.0** and end the three-way version divergence.

## Why now

Every realm's plan `001` is this migration (`citadel/docs/ROADMAP.md`, Phase 1); zoltraak goes
last — largest service, only one linking LuaJIT. Nothing else plans safely first: 0.16 rewrites
`std.net`, `std.fs`, `std.time` and `std.Thread` sync around `std.Io` across ~41 of 89 `src/`
files, so 0.15-shaped code written today is a second migration tomorrow. Tiger Style rides
along: that diff touches half a tree holding 5 asserts, 105 `std.debug.print`, 0/88 `//!`.

## Scope

Each item is one unattended cycle or less. Local builds stay reachable via 0.16's local
package override (`--dependency sailor=…`); only items needing *published tags* are blocked.

- [ ] **Clear the decks.** Untrack `src/.DS_Store`; drop the stale `.gitignore` entries the
      restructure left (`check_existing`, `main`, `verify_*`, `/test_*`); add `CHANGELOG.md`.
      Decide `wip/migrate-real-dump-restore` (real `MIGRATE` over DUMP/RESTORE, 295+/56−,
      tests included, green when written): rebase and merge it as its own PR — finished work,
      and item 9 rewrites the same `cluster.zig` networking, so landing it later means redoing
      it. Verify: no tracked `DS_Store`; that branch merged, or closed with the reason on it.
- [ ] **`tidy` build step.** `zig build tidy`, a dependency of `zig build test`: line ≤ 100,
      function ≤ 70 with a red zone of 71–72 for existing code, and a ban list — `catch
      unreachable` without a proof comment (15), `std.debug.print` (105), `std.time.*` (206),
      `usize` in wire/RDB/AOF formats, missing `//!` header (88/88). Per-file baselines in
      `tidy-baseline.zon` may only shrink. Verify: green, and a 101-column line fails it.
- [ ] **`build.zig` on 0.16.** `exe.linkSystemLibrary("luajit-5.1")`/`exe.linkLibC()` →
      `exe.root_module.linkSystemLibrary("luajit-5.1", .{})` / `root_module.link_libc = true`,
      likewise for the test artifacts and the LuaJIT paths. The first wall: nothing in `src/`
      compiles until this does. Verify: `zig build --help` under 0.16.0 exits 0, deps overridden.
- [ ] **Mechanical renames A.** `main() !void` + `argsAlloc` (1) → `main(init:
      std.process.Init)` + `init.minimal.args`; `GeneralPurposeAllocator` → `DebugAllocator`
      (3); `std.ArrayList(T){}` → `.empty`/`.initCapacity` (63 sites, ~40 files). Verify:
      those three error classes are gone from the `zig build test` probe log.
- [ ] **Mechanical renames B.** `mem.indexOf*` → `find*` across ~1050 call sites, driven from
      the mapping table in `zig-0.16.md` (`indexOfPosLinear`→`findPosLinear`, `lastIndexOf`→
      `findLast`) — **not** a blind `s/indexOf/find/`; plus the writer surface:
      `ArrayList.writer()` → an `Io.Writer` adapter (1), `pub fn format(w: *std.Io.Writer)`
      (5), stdout/stderr → `File.stdout().writer(io, &buf)` + `flush()` (5). Verify: no
      `std.mem.indexOf` left in `src/`.
- [ ] **`io: Io` through the public API.** Apply the convention recorded in
      `citadel/core/rules/zig-0.16.md` (settled by the sigil spike): `io: Io` is the first
      parameter after the receiver on every public fn touching fs/net/time/sleep/sync; `main`
      takes `init.io` and injects it into `Server`, `Storage`, AOF/RDB, replication; no
      library-side `Io.Threaded.init`. Verify: `tidy` gains a check that nothing in `src/`
      constructs an `Io`.
- [ ] **fs and time onto `Io`.** `fs.cwd()`/`fs.File` → `Io.Dir.cwd().openFile(io, …)` with
      vectored `readStreaming`/`writeStreaming` (8 sites: AOF, RDB, Sentinel config writing);
      `std.time.*Timestamp`/`sleep` → `Io.Clock.awake.now(io)` and `io.sleep(…, .awake)` (19
      sites: cluster, sentinel, blocking, latency, eviction, search, lua_engine). Verify:
      AOF/RDB round-trip tests pass on 0.16.
- [ ] **Thread sync onto `Io`, and cancelation.** `std.Thread.Mutex` → `Io.Mutex` (9: acl,
      config, client, defrag, lazyfree, memory, modules, slowlog); `Thread.spawn` (4) →
      `io.concurrent`/`Io.Group`. Add `error.Canceled` prongs to every exhaustive I/O error
      switch this surfaces — a swallowed cancelation is a leaked connection. Verify: those
      modules' tests green; `tidy`'s new ban on `else => unreachable` over I/O errors passes.
- [ ] **`std.net` → `Io.net`.** The architectural item: `network/tls.zig`, `replication.zig`,
      `redis_api.zig` and the `server.zig` accept loop (8 direct sites, the whole connection
      lifetime behind them). `Address.parseIp` → `Io.net.IpAddress.parse`, `listen(io, .{})`/
      `accept(io)`, `Stream.Reader/Writer` → `.interface`, `crypto.tls.Client.init(reader,
      writer, options)`. Budget two cycles. Verify: `redis-cli PING` round-trips, suite green.
- [ ] **Tests, toolchain pin and CI.** `std.testing.io` everywhere (never a helper shared with
      non-test code), `testing.tmpDir` options → `Io.Dir.OpenOptions`, any `testing.fuzz` →
      `Smith`; then `.minimum_zig_version = "0.16.0"`, dependencies bumped to the published
      tags, CI on `mlugg/setup-zig@v2` resolving from `build.zig.zon` (drop the hardcoded
      `version: 0.15.0` in both jobs). Verify: CI green on `main`.
      `blocked_by: zuda v3.0.0, sailor v3.0.0`
- [ ] **Assertion baseline.** Pre/post assertions on every public function of the five hot
      modules — `storage/memory.zig`, `protocol/{parser,writer}.zig`, `server.zig`,
      `commands/strings.zig` — starting from 5 asserts tree-wide: argument ranges, buffer
      bounds, RESP frame invariants, no aliasing on rewrite paths. Verify: `zig build test`
      green in Debug and under `-Doptimize=ReleaseSafe`.
- [ ] **Docs and release.** README rewritten against reality (500+ commands shipped, not
      "planned features"; Zig 0.16.0; working build snippet), CHANGELOG filled for 0.3.0,
      `build.zig.zon` version `0.3.0`, tag `v0.3.0` and a GitHub release per
      `citadel/protocol/VERSIONING.md`. Verify: `gh release view v0.3.0` exists.
      `blocked_by: zuda v3.0.0, sailor v3.0.0`

## Out of scope

- Wiring `src/storage/blocking.zig` into a real event loop (BLOCK-family stays on the polling
  loop) — it needs the event-loop refactor and belongs after `Io.net` lands.
- Splitting `storage/memory.zig` (15,650 lines) or the other 43 files over 800 lines; the two
  crashing RDB round-trip binaries; Sorted Set → `zuda.compat`; Phase 2–3 sigil/strata work.
- The ~730 stale test call sites: pre-existing, reproduce on 0.15.2, outside the test graph.

## Risks

- **Both dependencies must migrate first**: sailor v2.99.0 and zuda v2.0.4 fail their own
  `build.zig` on `linkLibC()` under 0.16, so no full build exists here until they tag v3.0.0.
  Mitigated by the local package override; only the two tagged items wait.
- **`std.net` → `Io.net` is a rewrite, not a rename**, sitting under TLS, replication and the
  dispatch loop — the one item that can spill past a single cycle.
- **Half the tree moves at once** (~41 of 89 files) on a codebase with 5 asserts, 44 files over
  800 lines and no external review surface — hence items 2 and 11 in the same plan.
- **Version bookkeeping is three-way divergent** (zon 0.2.0, old CLAUDE.md 0.2.13, tag v0.2.14);
  0.3.0 is set once. LLVM vectorization is off in 0.16 — expect CI benchmark drift not ours.

## Done when

- `zig build test` is green on 0.16.0 locally and in CI on `main`, with `mlugg/setup-zig@v2`
  resolving the version from `build.zig.zon` (no hardcoded `version:` left in `ci.yml`).
- `zig build tidy` is green and `tidy-baseline.zon` is strictly smaller than at item 2.
- `.minimum_zig_version = "0.16.0"`, dependencies at the `sailor v3.0.0` / `zuda v3.0.0` tags,
  and no `std.net.`, `std.fs.cwd`, `std.time.milliTimestamp` or `std.Thread.Mutex` in `src/`.
- `wip/migrate-real-dump-restore` is merged or closed, with the reason recorded on the PR.
- `gh release view v0.3.0` succeeds and this plan's tracking issue is closed.

## Version impact

**MINOR** — `0.2.0` → `0.3.0` in `build.zig.zon`, tag `v0.3.0`. zoltraak is a leaf service with
no kingdom consumers, so the 0.16 signature churn breaks no downstream API; what users see is
the toolchain requirement and the reconciled version claims — zon `0.2.0`, old CLAUDE.md
`v0.2.13`, tag `v0.2.14`, all three superseded by `0.3.0`.
